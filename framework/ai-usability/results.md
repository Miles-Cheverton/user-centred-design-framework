### Integrity skill forward-test

A fresh agent executed the actual check-project-integrity skill in check-and-fix mode against an isolated copy of the fictional project. It was not given the answer key or the injected fault list. The test copy had a broken decisions link and an additional reference to nonexistent EV-999.

It inspected all 18 project files, including complete tables and controls in nine workbooks. It repaired the decisions link, removed a verified redundant prototype mirror and moved non-ID explanatory text out of an ID-only field. Independent before/after hashes confirmed that only README.md and design-proposals.md changed; no files were added or removed and all nine workbooks stayed identical.

It preserved EV-999 as an unresolved reference rather than guessing a replacement or inventing evidence. It also identified two genuine gaps in the deliberately limited fixture: active UN-002 has no coverage record, and the keyboard observation is retained in evidence/NFR records but has not been synthesised into a finding despite the round's Complete status. It did not fabricate an assessment, researcher review or conclusion to repair these gaps.

The test supports the bounded repair and disclosure behaviour observed in this run. It does not establish that every AI tool will interpret the skill correctly, that it can detect unshared human knowledge, or that repairs are safe without current-state checks and appropriate access.

## Limits

This is one small, tool-assisted check in one available AI environment. It does not establish reliability across other models, larger projects, permission systems or retrieval configurations. The independent evaluator's underlying model version was not separately pinned or compared. Native Microsoft Excel interaction and human usability were not tested.

Re-run these questions when reference semantics or the reading workflow changes. Keep the answer key out of the answering model's context, record actual file-access coverage, and retain failures as well as successes.
