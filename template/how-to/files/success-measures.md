# Success measures

**Working file:** [success-measures.md](../../success-measures.md)

Define the small number of measures needed to understand whether the service is achieving its outcomes. Maintain results at their source and link them.


## First capture

Save a stable MET ID and what you intend to measure. Complete the definition, outcome link, source and interpretation responsibilities before using the measure. Unknown baselines and targets stay explicitly unknown.

## Define a measure

1. Start with an outcome and decide what evidence would show meaningful progress.
2. Define the measure precisely enough that two analysts would calculate it consistently.
3. Identify the available source and establish a baseline before claiming improvement.
4. Agree a justified target or direction and review interval.
5. Interpret results with user research and relevant differences between user groups.

## Fictional example

**MET-001 — Applicants who can identify their expected decision window**

For OUT-001, observe whether participants can correctly identify the expected decision window after submitting in the tested journey. Report the session counts and context; a small usability sample is not a population percentage. The baseline and target remain Not yet established until evidence supports them.

## Fields and sections

Use the small first capture to save a draft. Complete the relevant fields before relying on it; an unfinished record does not establish evidence, agreement or verification.

| Field or section | Needed when | What belongs here |
|---|---|---|
| Measure ID and name | At capture | Stable MET ID and understandable name. |
| Outcome IDs | Before use | One or more exact OUT IDs this measure helps assess. |
| Owner | Before use | Person or role responsible for definition and interpretation. |
| Review frequency | Before use | Useful existing interval or event; do not create a ceremony solely for this template. |
| Definition | Before use | Unit, population, time window and calculation where relevant. |
| Baseline | Before claiming a comparison | Value, period/date, supporting EV IDs and limitations; Not yet established if unknown. |
| Target | Before claiming a target is agreed or met | Intended value/direction, timing and basis; keep unknowns explicit. |
| Source and method | Before use | DOC IDs with exact versions/locations, or SES IDs; collection method, segments and exclusions. State source gaps. |
| Results and interpretation | When results exist | EV support and exact dashboard/report links with date/filter/snapshot; explain material context. |
| Review decisions | When the definition, target or interpretation changes | Record the actual DEC attribution for meaningful changes. |

## Keep it current

Update when results change the interpretation or the measure changes meaning. Keep enough definition history to understand comparisons. A changed population, calculation or source can break comparability. Record important changes and avoid silently comparing unlike results.

## Completion check

The measure has a clear connection to an outcome, an interpretable definition and a feasible source. Unknown values have not been invented.

## Practice basis

[GDS: setting performance metrics](https://www.gov.uk/service-manual/measuring-success/how-to-set-performance-metrics-for-your-service). The record structure is our implementation choice. Guidance reviewed: 16 November 2026.
