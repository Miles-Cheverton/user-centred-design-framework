# Add a user need

Follow the [shared skill rules](../README.md) and the [user-needs guide](../../how-to/files/user-needs.md).

## Procedure

1. Start from the need humans identified through analysis or explicitly propose. Establish who experiences it and what they need to achieve. Do not infer needs from a raw transcript. If a supplied feature request does not establish the underlying goal, return that question to the team rather than inventing the need.
2. Read relevant user groups and existing needs. Keep the existing UN ID when refining the same goal; do not merge materially different groups, circumstances or purposes merely because the wording resembles another row.
3. Tidy the human-supplied Need and Purpose into recognisable user language without changing their meaning. Capture the small initial record when evidence or purpose is still being established, following the guide's stages; unresolved meaning stays unresolved.
4. Resolve the exact UG IDs and any EV or FND support. Follow findings to their underlying evidence before claiming that they support the need. A stakeholder request alone can support a Proposed record, not an automatic Evidenced status.
5. Save the record with the human-established status when authorised; checking references alone does not establish Evidenced. Preserve replaced needs and exact replacement links; do not erase earlier understanding. Keep fulfilment assessment in user-need-coverage.xlsx, separate from whether the need itself is evidenced.

## Result

Return the UN ID, concise need and purpose, status and supporting references. Identify any missing user-group or evidence link. Do not claim that an evidenced need has been met or agreed for delivery.
