The full set of files is available when the corresponding work happens. There is no exercise to fill every file at setup. All substantive learning, needs, consequential decisions and retained design options must have an owning record, including contradictory and inconclusive findings and discarded options that taught the team something.

Raw material can remain in approved research and design tools. Register exact source locations and retain accessible text for its substantive meaning. State access or coverage gaps explicitly. Do not routinely copy delivery backlogs, operational systems or private data into this structure.

## File use

Edit each Excel register directly. The named main table holds one type of record. Dropdowns support consistent values. Guidance and fictional examples live in the how-to files; blank rows are not evidence.

Markdown files hold concise text and repeatable record sections. Bracketed text is a prompt to complete, not a project fact. An unknown can remain explicitly unknown until there is a useful way to resolve it.

The example folders RND-001, JNY-001 and PRT-001 show the structure for research rounds, journeys and prototypes. Their template documents and placeholder artwork do not represent completed activity. Use IDs consistently when creating real records.

Each research round can contain its discussion guide, questionnaire, original survey export, calculation working, human analysis notes and Whiteboard reference. The two survey workbooks are optional blank working aids, not additional central registers. Keep an original export in its supplied format rather than re-entering it. A live board remains in its approved tool; retain meaningful snapshots and human-authored text when needed to understand the work. Final findings and decisions keep their existing owners.

Update records as the work happens: capture learning after research, record a consequential choice when made, and amend a record when its meaning changes. Use the team's existing conversations; this template does not add a review meeting or reporting cycle.

## AI assistance

- Use a [prompt](ai-prompts/README.md) to answer a project question, prepare for refinement or check an evidence gap.
- Choose a [skill](skills/README.md) to draft, check or update specific records. Tell the assistant what to use and what to return.

Give the assistant access to this README and [AI guidance](ai-guidance.md), then the files needed for the task. For research, supply the team's conclusions and authorised sources so the assistant can document them or check citations. The [human analysis guide](how-to/evidence-and-interpretation.md#human-analysis-before-documentation) explains the team's part of that work.
