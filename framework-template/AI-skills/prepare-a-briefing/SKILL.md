# Prepare a briefing

Use the confirmed project folder (normally containing `document-tracker.xlsx`), not the installed or copied skill location. Resolve links from the canonical project path `AI-skills/prepare-a-briefing/SKILL.md`. Read the project’s `AI-skills/ai-guidance.md` [shared principles](../ai-guidance.md#shared-principles) and the applicable sections of `AI-skills/record-conventions.md` and record guides. If essential shared guidance is unavailable, say so; draft affected changes instead of saving. Continue independent, permitted work, including tasks limited to supplied files.

People establish findings, needs, fulfilment and decisions. Never invent records, IDs, sources or agreement. Respect access, consent and authorisation; cite exact sources and limits. Save only authorised changes, and report Saved and verified, Not saved or Save unverified.

## Prepare the brief

Confirm audience, purpose and [scope and working folder](../ai-guidance.md#start-with-the-task). Use the team's approved notes, decisions, relevant pending changes and [Find and explain](../find-and-explain/SKILL.md#answer-from-the-project-records) to establish the current position and its basis. Use [Check evidence and records](../check-evidence-and-records/SKILL.md#choose-the-check) for disputed, withdrawn, unverified or changed scope; distinguish current and historical evidence, agreed and pending choices, and simulated and implemented work.

| Briefing | Include |
|---|---|
| Refinement | Proposed work, need, outcome, agreed criteria and open choices. |
| Playback | Team findings, evidence limits and proposed or agreed next steps. |
| Phase review | Key decisions, evidence supporting or challenging them, uncertainty and open decisions. |
| Assessment or assurance | Applicable criterion and version, existing evidence/record IDs, evidence scope, gaps and responsible reviewer where known. No formal sign-off or claim of compliance without verified basis. |
| Handover | Current scope and decisions; exact design versions, requirements, verified test scope, key sources, owners and next steps where recorded. |

For an assessment against professional standards (for example GDS), verify applicable criteria using [professional guidance](../ai-guidance.md#check-which-guidance-applies) and map the existing evidence and gaps to each relevant criterion. Do not create another register. Leave formal sign-off to the responsible people.

Apply [cross-disciplinary guidance](../ai-guidance.md#advise-an-experienced-team) for the audience. For a release decision, show the user outcome alongside actual tests and release evidence, unassessed users/routes, staff impacts, and dependencies. Distinguish advice from the team's decisions. Return the requested format with [checkable citations](../ai-guidance.md#ground-claims) and explicit evidence gaps.
