# Capture or update records

**Skill revision:** 2026-11-26.2

Verify that this skill and the actual project copies of `ai-guidance.md` and `how-to/record-conventions.md` have the same revision before saving project changes. If a revision differs or cannot be verified, report the gap and limit work to reading, checking and drafting. Authorised framework upgrades may proceed using the [upgrade steps](../../how-to/README.md#upgrade-an-existing-project) to restore a matching set.

## Copy-and-paste example

> Use AI-skills/capture-or-update-records/SKILL.md. Propose updates from the team’s notes. Check them against the supplied transcript and project records. Give the exact sources, fill in details you can verify and flag missing information or disagreements for us to check.

## Propose or update each record

1. Confirm the working folder and sources using the [AI guidance](../../ai-guidance.md#start-with-the-task). [Check for relevant additional files](../../ai-guidance.md#include-additional-project-files) within scope. Use the [document tracker](../../document-tracker.xlsx) to find the owning file in the project folder, then read its capture rules. [File guides](../../how-to/files/)
2. Check for an existing match, revision or replacement. Keep the ID of the same record and check the next unused ID for a new one. Use exact versions where required. [Record conventions](../../how-to/record-conventions.md#canonical-relationships)
3. Start from the team's own notes or account of what they concluded or agreed. Check it against the supplied sources. Record what people established with the status and scope their sources support. Use Reviewed for a finding when the team agreed its wording and checked its sources. Use Draft if either is still open. Fill in verified details and exact citations. Point out relevant passages, possible matches and gaps for the team to review. Retain material disagreements and open questions. For a participant session, cite its SES ID, the exact notes, transcript or recording used, and a locator. For a saved record that needs a non-session citation, [reuse or add the DOC entry](../../how-to/files/source-register.md#first-capture) within the authorised update.
4. Save only as authorised. Before writing a controlled value, check that the target rule allows it. If a workbook lacks the required controlled value or you cannot verify it, return the proposed change and point to the [upgrade guidance](../../how-to/README.md#upgrade-an-existing-project). For the first Excel record, replace the **OVERWRITE ME** example and keep its ID if it fits. Preserve unrelated entries, named tables, dropdowns and [extra columns](../../ai-guidance.md#read-and-preserve-extra-workbook-columns). Verify new citation targets before linking to them. Reopen saved records to check their values, status and references. After a partial save, report which entries were verified and reuse them on retry.

| Material | Where to focus |
|---|---|
| Findings and observations | For a confirmed withdrawal, update the existing FND or EV row. Keep its ID, permitted citation and reason in **Evidence and source**. [Trace direct and dependent claims](../../how-to/record-conventions.md#trace-withdrawn-evidence), including research questions the affected findings answered. When authorised, add review notes to affected records without changing their judgements. Keep observations and exact citations with the team's conclusion. Use an EV row for separately cited evidence. With raw material alone, capture requested literal observations and leave synthesis for people. [Findings guide](../../how-to/files/findings-and-observations.md#withdraw-a-finding) |
| Team or stakeholder meeting | Check the human notes against the approved source. Propose records for significant choices and changes to project records. Flag unclear decisions, owners or conditions for confirmation. [Meeting follow-up](../../how-to/README.md#capture-what-changed-in-a-meeting) |
| Design choices | Record significant alternatives and the team’s rationale in [Decisions](../../document-tracker.xlsx). Record what the team learnt in [Findings](../../document-tracker.xlsx). |
| User need assessment | Update the existing UN row with the team's fulfilment judgement, exact scope, evidence and separate delivery choice. When a prior assessment no longer applies, retain its historical basis and flag the current scope for review. Use Withdrawn only when the team confirms the need itself is no longer valid. [User needs guide](../../how-to/files/user-needs.md) |
| Retired questions, rules or requirements | Use the owning guide for a confirmed withdrawal without replacement. Retain the stable ID and reason, and flag affected current records for team review. |
| Research materials | Link to exact retained versions in the protocol or session row. Use the protocol for debrief notes and board links. Link existing session notes with the roles and groups actually represented and the circumstances covered. Register cited board snapshots and other non-session sources by DOC ID. [Research materials guide](../../how-to/research-protocol.md#discussion-guides-surveys-and-whiteboards) |
| Journey | Link the exact diagram or its description. Use the description for the graphic, context, sources and design links. [Journeys](../../how-to/files/user-journeys.md) |
| Prototype | Link straight to the retained version in its own tool or format. Use a short note if the version needs context or setup instructions. [Prototypes](../../how-to/files/prototypes.md) |

Use the [guidance for experienced teams](../../ai-guidance.md#advise-an-experienced-team) when a record crosses disciplines. For example, if a design review agrees new wording, capture the agreed wording and version. Check separately whether policy approved the wording, developers released it and users understood it before recording any of those claims. Keep suggestions for a future test outside the agreed record until the team adopts them.

## File a chat attachment

When asked to file an attachment, use the [source register guide](../../how-to/files/source-register.md#file-a-source) to choose its approved destination. Use the file and existing records to establish what you can. Ask for missing details that affect the project, placement, access or the source version.

Check for an existing copy of the same version. Reuse a verified copy or save the attachment in its original format. Keep different versions separate and verify the saved file before adding or reusing a Source register entry when requested or needed for a citation.

If a step is blocked, say whether the file was saved and whether its entry was verified. Give the exact destination or draft register values where available. On retry, reuse any completed step.

Report the destination, verified ID if available, source, record status and [save result](../../ai-guidance.md#check-status-and-what-was-saved) for each change. Where a save is blocked, give the proposed fields ready to paste, identify the missing access or decision and say where the team can retain the source and pending change for a later session. Use the **Pending changes** location in project config when set and authorised. A later chat needs that record or handover to see it.
