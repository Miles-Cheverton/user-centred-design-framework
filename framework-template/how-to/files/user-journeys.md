# User journeys

**Working file** [user-journeys.xlsx](../../user-journeys.xlsx)

## First capture

Enter **ID** and **Version** for a journey or other service map used in research, significant decisions, substantive review or handover. Use a journey to show what people experience, a blueprint for backstage work, a process map for actions and decisions, an actor map for responsibilities or an information flow for information needs.

## Fields

| Field | What to enter |
|---|---|
| ID | Stable JNY ID. Use distinct IDs for competing alternatives. |
| Version | Exact revision, for example `v1`. Keep the JNY ID for revisions of the same journey. |
| Link | Exact map or its matching text description. Add this before others rely on the version. |
| Status | Draft, Reviewed, Selected, Discarded or Superseded. Confirm the status before treating it as the chosen direction. Record implementation evidence separately. |

## Check the map and its description

Use the [version description](../../journeys/JNY-001/v1/description.md) to record the purpose, groups, boundaries and matching graphic. Label stages and handoffs, and distinguish prescribed, observed and proposed steps. Cite the relevant rule, evidence or retained design. Flag disagreements and cite relevant selection, discard or replacement decisions.

Open both files before research or handover. Check that their versions, staff actions and supported routes match. The author resolves discrepancies. Retain versions that explain significant decisions or learning. [Worked handoff](../worked-service-handoff.md)
