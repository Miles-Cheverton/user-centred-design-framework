# Business rules

**Working file** [business-rules.xlsx](../../business-rules.xlsx)

## First capture

Use a BR ID and state when the rule applies and what the service must do. Choose Proposed while approval is unresolved.

## Fields

| Field | What to enter |
|---|---|
| ID | Stable BR ID. |
| Rule | The condition, required behaviour and known exceptions. Name any unresolved exception here and say what still needs deciding. Link a decision table if rules interact. |
| Source | The exact policy, specification, agreement or decision and its relevant section. Include a DOC or DEC ID when recorded and any uncertainty about applicability. |
| Status | Proposed, Approved or Superseded. Confirm the source and approval before relying on the rule. |

Keep each superseded rule’s wording, exceptions and source. Give each replacement its own BR ID. In **Rule** on the older row, list the exact successor IDs, for example `Replaced by BR-204; BR-205`. If the successor is unknown, say so there. Cite both old and new rules in any decision about the change.

**Example** `BR-201` proposes sending a collection message when depot staff confirm equipment is ready. `DEC-202` records the scope of the test.
