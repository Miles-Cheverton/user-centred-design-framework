# Constraints

**Working file** [constraints.xlsx](../../constraints.xlsx)

## First capture

Use a CON ID and describe the limit and what it affects.

## Fields

| Field | What to enter |
|---|---|
| ID | Stable CON ID. |
| Constraint | The practical limit and, where known, who can approve a change or what would need to happen. |
| Source | The exact policy, agreement or decision and its relevant section. Include a DOC or DEC ID when recorded and any uncertainty about applicability. |
| Flexibility | Fixed if the project cannot change it, Flexible if there is a route to change it, or Unknown while the team checks. |

Confirm the source and flexibility before relying on the limit. Review both when circumstances change. Record a removal or renegotiation in the [decision log](../../decisions.xlsx).

**Example** The team must use the approved identity service. An alternative needs architecture approval, so flexibility is Flexible.
