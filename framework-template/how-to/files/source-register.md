# Source register

**Working file (via document tracker)** [source-register.xlsx](../../document-tracker.xlsx)

## File a source

Put a commissioning brief, policy or other supporting document in [project sources](../../project-sources/) or keep it in its approved location. Keep research and design material with its activity. A team member can file the source and add its register row, or attach it in chat and ask the assistant to file and register it.

## First capture

Register a source when a record needs its DOC ID or the team needs to track its version or replacement. The assistant can add the entry as part of an authorised save that needs a DOC citation.

Check the exact path or URL and the version used. Reuse the existing DOC ID when they match. For renamed copies, reuse the entry when you can verify identical content and the same source version and origin. If any of these are unclear, flag the possible match. For a new source, enter the next unused **ID**, **Title** and exact **File or URL**. Add the date or version when known. Verify the entry before saving a record that cites it.

## Fields

| Field | What to enter |
|---|---|
| ID | Stable source ID, for example `DOC-001`. |
| Title | Source or page title. |
| Description | What it covers, who supplied it if useful, what it supports and key limits. |
| File or URL | Exact path or direct URL. Keep research and design material with its activity. |
| Date or version | Date or version used. For live pages, give the access date and retain an approved dated copy if you need to check exact wording later. |
| Superseded by | Exact DOC IDs of known replacements. Keep the earlier row so its citations resolve. |

For survey exports, record the questionnaire version, collection period and filters. Register cited calculations separately and link the export. For a cited Whiteboard, identify the retained snapshot, relevant area and access limits. [Research materials](../research-protocol.md#discussion-guides-surveys-and-whiteboards)

## Decide how much weight to give a claim

Check the author’s authority, the evidence, the date and whether the claim applies to this service and its users. For example, an approved commissioning brief can establish the budget while its demand estimate still needs testing. People judge the weight; AI can find exact passages and record the team’s assessment.

In [findings](../../document-tracker.xlsx), cite the DOC ID, exact version or path and page, section or other locator in **Evidence and source**. Put limits on a particular claim alongside that claim. If a withdrawal identifies a verified limit of the source itself, add that limit to **Description** with the affected scope and relevant FND or EV ID. Keep the original source and version where permitted. Follow the agreed retention and withdrawal procedure when a source or identifying details have to be removed. Preserve the DOC ID where permitted and leave a non-identifying explanation in **Description**. If the original locator cannot be retained, remove it and note that the source is unavailable. Flag the unavailable source and any affected evidence for team review.

## Record replacements

If a replacement covers part of a source, note which part in **Description**. If a source is out of date and its replacement is unknown, say so there and leave **Superseded by** blank. Check with the source owner when its currency is unclear.
